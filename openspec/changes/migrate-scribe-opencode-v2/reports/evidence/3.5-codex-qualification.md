## Native discovery semantics (static source, tag v2.1.2)

- `plugin/source-directory.ts`: children of `<config dir>/{plugin,plugins}/` are discovered; a symlink ending `.ts`/`.js` is admitted when `stat` (following the link) says file.
- `config/plugin/source.ts`: explicit `plugins` entries that resolve to a file are rejected ("must be a directory"), so owned-directory discovery is the only file-plugin lane. The reported local source is the link path, not the realpath.
- `plugin/src/source.bun.ts`: the dependency pre-scan resolves `../lib` against the link path (a nonexistent owned directory); on failure it only tracks/watches and never fails the load. The actual import is by the runtime loader, which resolves from the real file. Whether `../lib` reaches the delivered lib is therefore a runtime fact the fixture checks (module evaluation must succeed, and `deliveredLibResolutionMatches` verifies the realpath layout beforehand). If the runtime does not follow the symlink, the correct outcome is to stop and report rather than copy.
