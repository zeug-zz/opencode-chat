# Task 4.8 — Native restricted-review transport evidence

## Local implementation

The restricted-review provider now uses the captured native `OpenCode.make` client and active workspace directory. Readiness calls native `agent.get` for the exact agent/location and validates hidden subagent mode, native object model identity, configured system/step limits, and the required deny set relative to the last exact wildcard deny. Permission readback validation is an ordered structural proof, not a generalized policy evaluator: all rules must be well-formed with nonempty action/resource and effect `allow`, `ask`, or `deny`; earlier well-formed allow/ask rules may be shadowed by the last `*`/`*` deny, while every rule from that deny onward must be deny and contain all configured concrete/wildcard denies. Native `AgentInfo` readback is configuration evidence only, not proof of effective server/plugin enforcement.

Owned role sessions are created with the restricted agent, host-pinned model, workspace location, and explicit deny-only permissions. The bounded native session ID, returned agent/model/location, and prompt admission identity/text are validated before retaining or publishing results. Stage delivery waits for idle, records the newest assistant-message boundary (skipping descending idle/user/control records), stores the fixed role instruction through the native session instruction-entry context channel, and submits only the bounded packet via native prompt admission. Retrieval selects only the newest assistant snapshot, requires it to be newer than the boundary and have matching agent/model, finite explicit completion time, successful stop finish, and no error/tool content. Valid reasoning parts are ignored and never surfaced; only ordered text parts are joined and bounded to 8,192 characters. Empty content is textless and cannot succeed, while an explicit empty text part is accepted. It does not use V1 parts or stable-poll completion heuristics.

Native per-operation requests receive `RequestOptions.signal`; review cancellation interrupts then removes owned sessions, and direct deletion aborts that session's request controller before removal. Prompt admission boundaries are cleared before each stage attempt, so a failed later stage cannot reuse an earlier result. Review tokens, per-await session ownership checks, generation/invalidation checks, and captured-workspace checks prevent stale or foreign results. A validated late-created session is cleaned with bounded independent requests; failed removal retains ownership and blocks replacement reviews rather than claiming cleanup success or retrying. Error messages are fixed and do not expose SDK payloads.
