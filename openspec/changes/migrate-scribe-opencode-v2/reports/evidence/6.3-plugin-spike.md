## Reconnect diagnosis

The prior no-request reconnect idle was caused by the **test fixture lifecycle**: the intentionally uncaught-throw plugin initialized `throwNext = true` on every setup. Reconnect restarted the private child and reloaded that plugin armed, so the first post-reconnect context call could trigger the same uncaught throw as the dedicated failure scenario. The fixture now starts unarmed and is armed through its own RPC immediately before only the native-throw test. The defensive context plugin performs only synchronous bounded in-memory lookup in the context hook, catches internal errors, and fails open.

Final bounded probes after reconnect:

| Probe | Messages (count; roles) | Assistant/error | Provider | Hook counters | Provider lifecycle |
|---|---|---|---|---|---|
| Existing session with a brief put before reconnect | 3; user 1, assistant 1, other 1 | Exists; no error class | Request observed; brief absent | calls 0→1; internal exceptions 0→0 | Config still targets mock origin; listener active |
| Existing session with no brief ever put | 3; user 1, assistant 1, other 1 | Exists; no error class | Request observed; no brief | calls 0→1; internal exceptions 0→0 | Config still targets mock origin; listener active |
| New session after reconnect | 3; user 1, assistant 1, other 1 | Exists; no error class | Request observed; no brief | calls 0→1; internal exceptions 0→0 | Config still targets mock origin; listener active |

The reconnect probes therefore do not reproduce a native missing-brief/hook failure. They show the harness's re-armed throwing fixture was the source of the earlier silent idle; after making that fixture explicitly armed, each reconnect path completes through the provider with the brief absent.

## Native uncaught-throw residual limitation

The dedicated native-throw fixture is now explicitly armed only for its own test. Its turn completed `idle`, made no provider request, and produced a bounded message summary of 2 records (user 1, other 1), no assistant message, and no assistant error class. The throwing plugin and context plugin remained `active`; the private server remained ready, and a later ordinary turn completed and reached the provider. This is observed OpenCode 2.1.4 behavior when a hook throws uncaught. It motivates the production requirement that the Scribe context-hook body be total: `try/catch`, synchronous bounded in-memory lookup only, and fail-open/no injection on internal error. It does not fail criterion (e).
