## Fixture-owned paths

Each test creates a unique root beneath `tmp/scribe-v2-isolation/run-<unique>/` and removes only that root after verifying its canonical location and private owner marker. `OPENCODE_TEST_HOME` is set to fixture HOME because exact v2.0.32 `Global.Path.home` prefers it over `os.homedir()`; `HOME` alone is insufficient. Global data/cache/config/state/tmp roots derive from XDG roots, `OPENCODE_CONFIG_DIR` is passed to `Global.layerWith`, and `OPENCODE_DB` overrides the database filename under the isolated data root. The fixture layout is:

| Path relative to unique root | Purpose |
|---|---|
| `home/` | fixture HOME |
| `xdg-config/` | fixture XDG config root |
| `xdg-data/` | fixture XDG data root |
| `xdg-cache/` | fixture XDG cache root |
| `xdg-state/` | fixture XDG state root (includes isolated service state root `opencode/`) |
| `database.sqlite` | fixture `OPENCODE_DB` destination (not created/opened by this suite) |
| `tmp/` | fixture `TMPDIR` |
| `cwd/` | Node-only fixture child working directory |

The helper rejects non-canonical/symlink roots, lexical traversal, symlinked descendants, altered ownership markers, unallowlisted environment entries, and credential-like environment keys. The fixture child gets only the exact generated HOME/XDG/OPENCODE_DB/TMPDIR environment; it does not spread `process.env`. Its executable is `process.execPath`, never `opencode`; output is capped and its runtime is bounded with TERM/KILL cleanup. Tests also inject a parent-only sentinel and confirm it is absent in the child.

In `server-process.ts`, `ServiceConfig.options/read`, incumbent lookup, service registration, and service remote tunnel are only entered for service mode. Default mode does not read service config or register a service. It binds `127.0.0.1` by default unless a hostname is supplied; task fixtures do not launch it.
- Default mode obtains password from `OPENCODE_PASSWORD` or generates random bytes in memory, and prints the generated password to stdout if no environment password was provided. This task reads no secrets and launches no CLI, so the printed-password behavior is documented as a warning, not exercised.
