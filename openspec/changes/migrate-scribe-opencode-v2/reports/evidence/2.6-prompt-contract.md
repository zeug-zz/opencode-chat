# 2.6 Prompt and cancellation mapping — bounded partial implementation

Status: **PARTIAL; Task 2.6 remains unchecked.** Native `session.prompt` admission, attachments, agent/skill mentions, model/effort selection, and `session.interrupt` are implemented on the private V2 client. This maps the mock-provider contract only; prompt completion remains event-owned (Task 4.4), and provider-specific cancellation is not established beyond the accepted native built-in mock lane.

## Implemented mapping

- `sendMessage` uses `v2Client.session.prompt({sessionID,text,files?,agents?,skills?})`; no legacy SDK prompt route is used. Its resolution denotes native inbox/user admission, not execution completion.
- User text remains the prompt text. Bundled commands use only the already-selected host template and exact `$ARGUMENTS` substitution; an unknown command preserves user text. No arbitrary command or shell execution is introduced.
- Attachments are `{uri: pathToFileURL(absolutePath).href, name}`. The host resolves paths but does not read attachment contents.
- Primary agent selection uses session-scoped `session.switchAgent` before admission; `options.agent` remains an agent mention in `agents`, not primary-agent selection. These operations and prompt admission share the existing per-session queue.
- A specified model and optional effort use `session.switchModel`; effort-only selection resolves the current session model from native `session.get`. No model/effort mutation is sent when both are omitted, leaving server defaults intact. No persistent config endpoint is used.
- Skill selection resolves the native skill ID cached from `skill.list`; synthetic slash text is not sent as a substitute. Skill selection before native catalog resolution fails explicitly.
- `system` is delivered through reserved session instruction key `scribe.prompt-context`, with its exact value as a string. Before changing or removing the entry, the adapter calls native `session.wait` (bounded by a 30-second request AbortSignal), re-lists, and mutates only that reserved key. It does not remove the entry at prompt admission: it remains available throughout native execution and is changed/removed before a later adapter prompt. Other instruction keys are left untouched. A wait timeout/error prevents the prompt from being admitted; there is no replay.
- The pinned `instruction-entry.ts` source proves string values render verbatim in `<context key="...">` blocks; `InstructionState.initial` flows through `SessionHistory.entriesForRunner` and `SessionModelRequest.baseTranscript` as a system part. Later changes/removals are durable `SessionEvent.InstructionsUpdated` text (supersede/disregard narration), not converted to user prompt text. This is source evidence, not yet provider-visible runtime evidence.
- `abortSession` calls native `session.interrupt` outside the per-session prompt queue, so it is not blocked behind a quiescence wait or prompt admission. A false native acknowledgement is surfaced as failure, not represented as successful cancellation.
