# 4.4 Event translation and stream completion — bounded lifecycle chunk

Status: **PARTIAL — native SSE transport, lifecycle/session-status, assistant header, text/reasoning, step completion, and bounded tool-event translation implemented and hermetically verified.** This lifecycle chunk fetches authoritative snapshots for native session creation and the explicit metadata-change allowlist, and emits deletion as identity only. Lifecycle negative/race and per-session deletion-state coverage are now included. The full Task 4.4 remains unchecked because form translation is still outstanding. No actual OpenCode CLI, provider, plugin, host, or live-service operation was run.

## Implemented

- Event delivery now uses the pinned `@opencode/client@2.0.32` `event.subscribe({ signal })` AsyncIterable, whose exact declaration is `subscribe: (requestOptions?: RequestOptions) => AsyncIterable<EventSubscribeOutput>`. Frames are consumed as native flat `{ type, data }` events; the old `client.global.event({}).stream` transport and SDK `Event` import are absent from the production event path. Legacy SDK methods remain for operations not yet ported.
- Resubscription aborts the prior stream before opening one new subscription. Connection and stream generations plus the captured AbortSignal guard every yielded frame, so stale iterations after resubscribe/disconnect are ignored. An unexpected end or opaque iterator error calls the availability callback with a fixed disconnect message; exception contents are not surfaced or logged. Explicit disconnect/abort is not reported as a stream failure.
- Native `session.execution.started` maps to domain busy; `succeeded` and `interrupted` map to idle; `failed` emits a generic redacted `session.error` and idle. Native `session.status` maps only its exact busy/idle variants. `session.compaction.ended` maps to the existing `session.compacted` refresh trigger. Only a native `server.connected` frame with valid empty `data` emits the connection marker.
- The minimal stateful mapper is created fresh per SSE subscription. `session.step.started` publishes a validated assistant `message.updated` header with native operational agent/model IDs and `data.started` time; pinned native `ModelRef.id` maps to domain `modelID` (the legacy `modelID` wire field is not accepted). Positive step/text/reasoning/failure fixtures are checked against the pinned `V2Event` types. Text started/delta/ended maps to a stable derived part ID, empty initial `TextPart`, `message.part.delta`, and full terminal text with start/end timestamps. Reasoning started/delta/ended maps to the current domain reasoning event family using the same exported stable ID derivation.
- A valid `session.step.ended` updates the assistant header with finite cost, validated token usage, finish, and completion timestamp, then emits `session.next.step.ended`. Step failures update only a previously started assistant message with a fixed opaque error; raw provider error/state/metadata fields are not copied. State clears on step completion/failure or session execution terminal events. Unknown step ends without an active header are ignored.
- `session.idle` is ignored so it cannot deliver a second completion transition. Session created/updated/deleted frames are not converted into fabricated `ChatSession` values; authoritative event-driven fetch translation remains deferred. Unknown/malformed/non-lifecycle events are ignored. The `server.connected` marker is now an explicit `AgentEvent` union variant; no event cast is used. Each listener exception is isolated; bounded diagnostics include only event type and allowlisted error class, never payloads.
- Durable event-ID deduplication was not added: the pinned subscription is live-only and this chunk does not implement replay/reconnect snapshot handling.
- Native tool input started/delta/ended, called, progress, success, and failure frames now update existing `ToolPart`s. Input remains pending while streaming; only `called` supplies the structured input and transitions to running. Tool part/call identity uses native tool ID, with no invented timing or parent metadata; progress and result metadata are limited to validated public JSON metadata. Success and failure content use the existing native ToolContent text/file renderer; failures are opaque while retaining meaningful partial content and native `executed`. Provider state fields are never copied. Unknown, malformed, orphan, and post-terminal tool frames are ignored without mutating active state; per-subscription tool state clears with assistant/session terminal state.
- Native `session.created` and the explicit `session.renamed`, `session.metadata.updated`, `session.agent.selected`, `session.model.selected`, `session.usage.updated`, and `session.viewed` triggers perform one ordered `session.get({ sessionID }, { signal })` and emit only after the same stream-generation/abort guard passes. `mapV2Session` validates the authoritative response and exact requested ID/workspace; opaque fetch/mapping failures are skipped. Malformed IDs and unlisted session events do not issue reads. Native deletion emits `{ info: { id } }` only, clears matching mapper and pending-question state, and does not fetch after deletion. The core deleted-event type was narrowed to minimal identity after confirming consumers use `info.id`.
- Lifecycle focused tests also cover typed created/renamed/deleted frames, successful snapshot mapping, wrong returned ID/workspace and rejected GET without lifecycle emission while later status frames continue, resubscription while a GET is pending (old result ignored), malformed identity causing no GET, deletion with no GET, and selective assistant/tool/question mapper state plus adapter pending-question cleanup for only the deleted session.
- Progress updates preserve the prior `executed` field and place the latest public progress payload under the canonical `metadata` field, matching snapshot ToolPart metadata shape, including Code Mode `toolCalls`. Mapper tests cover first and repeated progress for `executed: true` and `false`. `ToolPartView` accepts these existing ToolParts but does not currently render progress metadata; this verifies adapter retention only, not UI progress rendering. No UI change was made.

### RC19 adapter reasoning-stream diagnostic handoff (2026-10-27)

- Added a content-free per-prompt summary to the existing adapter prompt-diagnostic lifecycle. The fixed record shape is `[opencode-chat] prompt diagnostic attempt=<numeric> stage=reasoning-stream outcome=<idle|error|stop> nativeReasoningEvents=<n> mappedReasoningEvents=<n> publishedReasoningEvents=<n> mappedDeltaCharacters=<n>`; all four counts are numeric, zero-valued fields are always present, and counters saturate at 1,000,000 events / 100,000,000 mapped JavaScript string code units.
- Native counts are taken at the current live SSE boundary for a matching tracked session/client/generation/workspace. Mapped counts are the mapped `session.next.reasoning.*` events; `mappedDeltaCharacters` sums only accepted mapped delta `.length`. Published counts are adapter event-publication calls, including the existing prompt-admission buffer flush. If terminal arrives while mapped reasoning events for that attempt remain buffered, summary emission waits until flush/discard so the publication count is not finalized early; product event ordering is unchanged.
- Correlation uses only the existing bounded prompt-attempt registry; unmatched hidden-reviewer/foreign sessions and stale subscriptions are not counted. Reconnect/disconnect cleanup emits no stale summary. A summary means the adapter called its publication path; it does not establish webview/DOM rendering.
