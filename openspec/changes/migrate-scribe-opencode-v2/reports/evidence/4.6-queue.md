## Reproduced missing-busy defect and fix

The positive regression is retained separately: after the first `sendMessage` resolves, with no initial busy event, reconnect idle dispatches the second prompt exactly once; duplicate idle does not dispatch the third before the second prompt's busy/idle completion. The original red run reproduced the defect at line 3184: actual dispatched texts were `["first"]`, not `["first", "second"]`.

The host now tracks admission by current dispatch identity. Reconnect idle can settle the busy guard only for the same prompt that was successfully admitted before the reconnect marker. A dispatch still awaiting admission is shielded from that snapshot; every queued dispatch replaces the token, and stale settlement cannot mutate the replacement queue state. No prompt is replayed.

Four deterministic deferred-promise negative tests cover unresolved admission at reconnect, recovery busy followed by idle, deleted queue replacement with late admission, and an older dispatch settling after a newer dispatch begins. The positive regression confirms duplicate idle does not drain the next prompt early.
