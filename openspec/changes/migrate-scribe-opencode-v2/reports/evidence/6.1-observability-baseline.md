## Instrumentation

Reasoning diagnostics use the existing extension-owned `OpenCode Scribe` LogOutputChannel. A single per-host reporter accepts only fixed stage/outcome labels and finite nonnegative elapsed milliseconds; its total cap is 128 records across repeated and distinct events. Invalid labels and invalid numeric values are discarded, finite oversized values are clamped to 60,000 ms, and sink/clock exceptions are nonfatal. If no channel sink exists, the reporter uses bounded `console.info`; a configured but throwing sink does not fall back to console.

The host reports initialization, runtime/provider readiness, adapter availability or fixed absence reasons, architect/AF/critic/total preflight outcomes, reasoning-runtime and assist UI publication attempts, and dispatch completion/failure. Prompt/session/model data and runtime error text are not passed to the formatter. The current pre-screen is not implemented and is explicitly reported as `not-implemented` / `not-measured`; no pre-screen metric is fabricated.

Timings use an injectable monotonic clock seam and are formatted as numeric milliseconds only. Publication latency covers the synchronous host `postMessage` invocation, not webview delivery; dispatch latency spans `dispatchPrompt` through `sendMessage` resolution and therefore includes the current preflight path. The diagnostic callback is observational: preflight order, admission, progress, budgets, cancellation, and existing dispatch behavior remain unchanged. These observations do not prove that a host caused a missing or delayed result.
