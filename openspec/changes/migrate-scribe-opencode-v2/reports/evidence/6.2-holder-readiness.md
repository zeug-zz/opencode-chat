# Task 6.2 — Restricted-review holder and readiness

## Implementation

- Bootstrap uses a hidden native-default reviewer without a literal model field. The agent resolves the effective default only through the location-bound native API, validates the response and workspace, then creates a provider pinned to the active client and connection generation. Null, malformed, failed, or stale resolution returns a fixed unavailable classification; it does not consult a catalog, Scribe preference, UI selection, or write configuration.
- The host holder owns each active provider/adapter/controller binding. AF preflight remains activation-scoped; when AF is not ready the holder reports the fixed unavailable state without constructing a reviewer. Successful connection and `server.connected` paths rebind and rerun readiness; stop/failure invalidates the holder, cancels assist work, removes stale bindings, and republishes `reasoningRuntime`. Hidden-session cleanup is awaited before reconnect shutdown and deactivation.
- Late binding/readiness results are revision-scoped: stale work can invalidate/dispose only its captured provider/binding and cannot clear a newer available snapshot. Diagnostic timing uses the safe reasoning clock; clock and sink failures remain nonfatal.
- Restricted permissions now explicitly deny native `execute`. The unset preference continues to resolve enabled only while runtime is available; explicit user `false` and workspace opt-out remain effective, with no activation-time preference writes.
- Diagnostics are limited to provider/adapter stages, fixed outcome labels, and bounded elapsed time. No model identity, raw error, prompt, path, credential, or configuration content is recorded.

## Native-default inheritance validation

- The inspected schema is `@opencode/client@2.1.0`'s generated `AgentInfo` in `dist/promise/generated/types.d.ts`: `model?: ModelRef` is optional (type declaration around lines 2898–2910). Scribe's `RestrictedReviewAgentEntry.model` is optional, and `buildRestrictedReviewAgentEntry` omits it when native-default resolution is selected.
- Readiness intentionally requires both the hidden agent's returned `entry.model` and the native-default configuration's `model` to be `undefined`. A focused negative test returns a nonempty hidden-agent model distinct from the UI-selected model and confirms readiness rejects it; the positive test confirms an omitted model passes after the effective default is resolved and pinned for the provider.
- This is schema/source and unit-test evidence only; no actual-host runtime qualification is claimed.

## Stale not-ready cleanup race correction

- What: a late cleanup for an older binding could clear a newer ready binding after its asynchronous adapter disposal completed.
- Fix: release the stale provider ownership before awaiting disposal and avoid clearing holder state afterward.
- Test: `keeps a newer ready binding when an older not-ready binding disposal resolves late`.
- Results: regression test failed against the original cleanup path (new binding was cleared); passed with the ownership-release fix.
