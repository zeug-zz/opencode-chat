# 2.1 Private launch lifecycle — local primitive WIP

Status: **Primary accepted Task 2.1's local implementation and production-helper lifecycle evidence only.** The authenticated helper is called by the ordinary executable path, VS Code sandbox wrapper path, and selected nono path; the agent supplies the returned authorization header to the existing client. Acceptance covers fake-backend agent tests plus one disposable production-helper run on the selected macOS executable. It does not qualify GUI/extension-host behavior, actual VS Code or nono runtime boundaries, other OS cleanup, native policy, or functional migration parity; tasks 2.2, 3.1 and subsequent operation-mapping tasks remain separate and unchecked.

`src/private-v2-server.ts` accepts the already-selected/wrapped foreground `serve` command and argv, shell mode, cwd, environment, expected V2 version, and injectable spawn/fetch boundaries. Separate bounded stdout/stderr consumers retain no diagnostics; only newline-complete stdout lines can supply the exact foreground markers. Endpoints are restricted to literal `127.0.0.1`, a nonzero port and bare origin. The password is held only long enough to form in-memory Basic auth for username `opencode`.

An opt-in disposable actual-binary check is available in `src/__tests__/private-v2-server.integration.test.ts`; default execution skips before resolving or launching a CLI. It requires both `OPENCODE_CHAT_RUN_V2_LIFECYCLE=1` and an explicitly supplied absolute `OPENCODE_CHAT_V2_SPIKE_EXECUTABLE`. The test uses `createV2TestIsolation`, rechecks the ambient system/managed config gate immediately before launch, calls the production helper directly with the pinned `2.0.32` serve command, checks unauthenticated rejection and authenticated identity/version, bounds the lifecycle to 30 seconds and six requests, awaits helper close, verifies authorization clearing, and removes the isolation root. The pinned generated client returns `/api/info` and `/api/location` JSON directly from `request()`; these readiness endpoints must be validated as plain records, without unwrapping a `.data` envelope. A unique redacted `result.json` is written under `tmp/scribe-v2-migration/lifecycle/<run-id>/`; BLOCKED and FAIL evidence is persisted before teardown and is never replaced by a later run. Its `qualification` is deliberately `PRODUCTION_LIFECYCLE_HELPER_ONLY`, not host, provider, plugin, retention, or client-mapping qualification.

Readiness has one overall AbortController deadline, rejects redirects, bounds response bodies before JSON parsing, and validates plain record envelopes. Authenticated `GET /api/info` must match expected version, spawned PID, and exact endpoint; authenticated `GET /api/location` must report the exact cwd. Failures use bounded code-only errors. Cleanup is idempotent/shared across callers, surfaces cleanup failure, and clears the private non-enumerable header object. After readiness, output is drained without retention and an optional callback receives only opaque exit/error state. POSIX cleanup targets the owned process group with TERM then KILL and reaps the leader; Windows uses bounded child TERM/KILL/reap without a process-group guarantee. Production tests now assert the helper close/reset/reconnect boundary, helper lifecycle callback behavior, and MCP attribution without retaining child output; plugin-fallback classification remains pending.

The first primary live qualification did execute the explicitly selected OpenCode 2.0.32 binary in the isolated fixture; it launched no provider/plugin and touched no user configuration. Its preserved failure evidence is `tmp/scribe-v2-migration/lifecycle/d77937fe-ee6a-42f2-b1fd-a2714d889fdf/result.json`: status `FAIL`, failure code `readiness-failed`, one API request, and both fixture/state roots removed. Primary source review confirmed the cause: readiness incorrectly required the generated client's `.data` wrapper, although `/api/info` and `/api/location` return raw JSON; `session.create` is a different operation that explicitly unwraps `.data`. This correction changes the helper and its fake fixtures to require the exact raw-record shapes, and rejects the old wrapped shape. The original failure manifest is retained unchanged.
