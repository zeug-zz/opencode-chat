# 4.3 Session messages, parts, forms and attachments — bounded message chunk

Status: **PARTIAL — native message history/snapshot mapping, permission event/reply mapping, and bounded native question-form mapping/reply/cancel are implemented and hermetically verified.** Attachment UI/host round-trip and end-to-end host UI routing remain unverified; Task 4.3 remains unchecked. No actual CLI, provider, plugin, host, live service, configuration, or credential operation was used.

## Implemented in this chunk

- `getMessages` now uses pinned `@opencode/client@2.0.32` `client.message.list({ sessionID, cursor? })`, never `session.message.list` or the legacy SDK route. It collects `cursor.next` pages up to the existing 1,000-page safety bound, rejects malformed responses, repeated cursors, repeated/invalid message IDs, and exhaustion of the bound rather than returning partial history. The native message records have no `sessionID`; request scoping is therefore the exact `sessionID` argument.
- The explicit native mapper emits only native `user` and `assistant` messages. Other known native system/synthetic/selection/compaction/skill/shell/idle control/context records are omitted instead of being converted to user text. User and assistant message identity, role, session scope and timestamps are mapped explicitly; assistant model uses native `model.id` (not a guessed `modelID` wire field), and validated cost, token usage, finish and an opaque failure indicator are retained.
- User text, URI-backed and inline file parts, and agent/skill mentions receive deterministic IDs. Skills map to the new provider-neutral `SkillPart` (native skill ID and name), never to an agent. `FilePart` retains native URI, MIME, optional name, description, and mention range/text; absent names use a decoded URI basename or `Attachment`. Native inline data is base64 encoded in the pinned message contract: the inspected source `tmp/scribe-v2-migration/spike-source/continuation/prompt.ts` creates `PromptBase64` from `Buffer.toString("base64")` and sets `source.type: "inline"` for data-URI inputs. The mapper accepts only canonical standard base64 and a validated MIME type before constructing a data URI; it does not read files or fetch attachments.
- Assistant text and reasoning part IDs use the same exported `deriveV2EventPartID(kind, messageID, ordinal)` helper as native SSE snapshots, with content ordinal, so history reconciles with streamed content. Reasoning timestamps, tool identity/name/input, completed text/file output, error state, native public metadata, timestamps and executed flag are explicitly validated and mapped. Tool-file output includes the source URI and MIME/name in the existing plain-text output; inline data URIs are not copied into tool output. Opaque provider transport states are excluded. Streaming tools map to the existing running state. Tool and assistant failures stay visible through fixed opaque error messages; raw provider error details are not copied.
- Existing legacy mapper exports are retained for remaining callers. No UI, permission/form, reply, host-routing, or lifecycle policy changes were made.

## Permission event/reply chunk

- Native `permission.asked` frames map `data.id/sessionID/action/resources/save/metadata` explicitly to the existing domain permission identity and fields; optional native tool `source.id` maps to the domain tool `callID`, preserving the native request identity required for pending-permission clearing. `permission.replied` preserves native `sessionID`, `requestID`, and the exact `once | always | reject` decision union.
- Frames with missing/oversized IDs, invalid arrays, non-object/non-JSON metadata, malformed source, invalid session IDs, or unknown reply values are ignored. Native envelope metadata and unrelated provider state are never copied. Public permission metadata remains available to the existing host retention confirmation gate; the existing host redaction before Webview delivery is unchanged. No retention authority or host behavior was added.
- `replyPermission` now uses only native `client.permission.reply({ sessionID, requestID, decision })`, rejects invalid IDs/decisions, queues by session, and rejects completion if the connection generation/client changed during the reply. No automatic retry or replay occurs; legacy SDK permission reply is not called.
- This is adapter/mapping evidence only. The existing host retention gate/redaction path was inspected but its service test and actual retention service were not run in this bounded chunk; host UI routing is not claimed as qualified.

## Native question-form chunk

- Native `form.created` is handled before the ordinary top-level `data.sessionID` guard because the pinned event nests identity in `data.form.sessionID`. Only exact `metadata.kind === "question"` forms with bounded native IDs, native tool message/call identity and contiguous ordered `q0...qN` string/multiselect fields map to the existing `question.asked` domain event. No Scribe-only question-count cap is imposed. Options are accepted only when `value === label`, preserving faithful domain answer values; header, question text, multiplicity, and custom-entry semantics are retained. Other form kinds (including OAuth/credential forms), malformed fields, duplicate IDs, and arbitrary answer shapes are ignored.
- Only forms observed as validated question creations in the current event mapper may produce `question.replied` or `question.rejected`. Answer keys are checked against their original order/types; partial and unanswered fields are allowed (the native question plugin serializes missing answers as empty lists), while unknown keys and invalid selected options for non-custom fields are rejected. Cancellation uses the existing rejected event without inventing model-facing feedback.
- The adapter records the validated request/session/field schema and captured client generation before delivering `question.asked` to listeners. `replyQuestion` encodes single-select to a string, multiselect to a string array, and unanswered fields as omitted keys, via only `client.session.form.reply`; rejection uses only `client.session.form.cancel`. Both operations share a minimal per-form in-flight guard; duplicate concurrent reply/reject attempts do not replay, while an API failure releases the same still-current entry for retry. Completed operations remove only their own pending generation. Invalid counts/types/options, orphan/stale IDs, disconnect/resubscribe state, and stale-generation completions fail closed. External reply/cancel events clear current pending entries. Ordinary busy/idle does not clear forms. No generic form API, OAuth/credential surface, or claim that native cancellation interrupts the underlying execution was added.
- A hermetic event-stream-to-`IAgent.replyQuestion` test proves registration precedes listener delivery and exercises exact single/multiselect/custom/unanswered wire values. Additional tests cover valid forms beyond 32 questions, custom-false multiselect option validation, concurrent reply/reject exclusion, and retry after a failed API call. Mapper tests cover ordered identity, native option-value equality, non-question filtering, reply/rejection, cancellation and malformed/orphan forms. Existing webview `useQuestions` event consumers remain the routing target; host/UI tests and attachment UI/host round-trip were not run and are not claimed as qualified. Authoritative pending-form recovery after SSE resubscribe is deferred to Task 4.5 and is not implemented here.
