## Isolation contract comparison

- Global roots are unchanged: home uses `OPENCODE_TEST_HOME ?? os.homedir()`;
  config/data/cache/state derive from XDG roots; tmp derives from
  `os.tmpdir()/opencode` (therefore the isolated child must set `TMPDIR` before
  process start); database path honors `OPENCODE_DB`. `OPENCODE_CONFIG_DIR`
  overrides the config root.
- Config discovery is unchanged across platform system roots, macOS managed
  plist roots, global/explicit config, ancestor project discovery, and global
  and ancestor `.agents` / `.claude` discovery. Neither version offers a CLI
  switch disabling system/managed discovery. Existing project-disable flags
  are `OPENCODE_CONFIG_PROJECT_DISABLE` and alias
  `OPENCODE_DISABLE_PROJECT_CONFIG`; existing Claude disable flags are
  `OPENCODE_DISABLE_CLAUDE_CODE` and
  `OPENCODE_DISABLE_CLAUDE_CODE_SKILLS`. Model fetching is disabled by
  `OPENCODE_DISABLE_MODELS_FETCH`. All were present in the old source; the
  current helper's exact child environment sets project disable, Claude
  disable, and model-fetch disable and does not inherit host environment.
- Config content/file inputs remain `OPENCODE_CONFIG` and
  `OPENCODE_CONFIG_CONTENT`; neither is allowed into the fixture environment.
  Empty fixture config/data/home roots remain required. No changed config,
  model-fetch, Claude, `.agents`/`.claude`, plugin, or skills discovery root
  was identified in the compared files. This is static path/source analysis,
  not proof those runtime reads cannot occur.
- Default foreground mode still differs from service mode: service config
  read, incumbent/service lookup, service registration, and tunnel behavior
  remain service-only. Default serve does not call `Service.ensure` or
  register itself. Default serve may generate an in-memory password and print
  it to stdout when neither `OPENCODE_PASSWORD` nor
  `OPENCODE_SERVER_PASSWORD` is provided; both versions have this behavior.
  The fixture must keep both absent and must not launch/attach to a server as
  part of this static task.
- The exact environment contract remains an isolated HOME/XDG config/data/
  cache/state, `OPENCODE_TEST_HOME`, `OPENCODE_CONFIG_DIR`, `OPENCODE_DB`,
  project-local `TMPDIR`, existing discovery-disable flags, no inherited
  `PATH`, config-content overrides, passwords, or auth/credential variables.
  Use a newly created, empty owned project root and path-only system/managed
  inspection immediately before any separately authorized child launch.
