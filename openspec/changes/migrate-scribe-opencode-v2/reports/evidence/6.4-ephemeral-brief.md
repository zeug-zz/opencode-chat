## Implementation

- Added the tool-less plugin at `packages/agents/opencode/src/scribe-context-plugin/`. It has no tools, network/file I/O, or persistence; its in-memory state is bounded to 16 entries, 4,096 JavaScript string characters and 16,384 UTF-8 bytes per brief, and 128-character session/turn keys matching `^[A-Za-z0-9._:-]+$`. Its production RPC exposes only `put` and `clear`; the RPC schema and handler enforce the shared character and byte limits.
- The `session.hook("context")` body is synchronous and wrapped in `try/catch`; it only performs bounded in-memory lookups and injects into matching Scout context. An internal hook error fails open without injection. A prompt hook binds/invalidates the active turn.
- The extension copies both plugin files into `dist/scribe-context-plugin`. Before overlaying that path into the private server, the host reads the two files and checks the pinned composite SHA-256 (`package.json\0` + manifest bytes + `\0server.js\0` + source bytes): `954d42c78a4475d257925c3117cdc5108fcee0dcc0a6b492ca6a493c6217c6a8`. Missing or mismatched bytes yield the fixed `bundled-plugin-unavailable` reason and disable assist only. The source is appended to inherited plugin sources in the process-scoped launch configuration; no user/project/global configuration is written.
- The agent package exports the shared 4,096-character and 16,384-byte limits. The host composer uses those constants for both fit checks, and host delivery and agent RPC admission independently reject out-of-bound briefs. The self-contained plugin literals and both RPC schemas are tested against the exported constants.
- Boundary coverage accepts an exact 4,096-character composed brief containing multibyte text through the host, agent API, and bundled plugin handler. 4,097-character and over-16,384-byte inputs are rejected at the host/agent/plugin boundaries; host tests verify the unchanged prompt is still dispatched without a turn ID.
- `IAgent` exposes native reasoning-assist turn-ID creation plus only the narrow brief `set`/`clear` operations; the adapter sends the native turn key as prompt ID and uses the plugin RPC with a bounded timeout and connection-generation checks. The host queues brief operations and clears state on turn idle, Stop/abort, next prompt, reconnect, session changes/deletion, and failed dispatch. Failed delivery omits the turn ID and still dispatches the prompt.
- Turn-ID provenance: the orchestrator's `promptToken` remains a UI/progress token only. The host obtains a `msg_` + 32 lowercase-hex native ID from `IAgent.createReasoningAssistTurnId()`, uses it for brief storage and `SendMessageOptions.turnID`, and the agent validates the native format before the plugin RPC or prompt request. The agent validates the returned user-admission `id` against it. Agent/plugin tests pass that admitted native message ID as the production plugin prompt hook's `event.messageID` and verify matching context injection; the host integration test also exercises exact-maximum host → agent API → bundled plugin RPC acceptance and matching-turn hook injection.
- The brief is no longer appended to or passed through `scribe.prompt-context`. Existing generic base-system prompt handling remains unchanged and receives only the base system prompt.
- Integration exposed two dispatch regressions: awaiting a no-op clear delayed ordinary FIFO dispatch, and failure cleanup referenced a try-local `assist` binding. Clearing is now awaited only when brief state/operations exist, and the binding is available to failure cleanup; regression tests cover both paths.

- **Defect and fix:** the first opt-in run proved that forwarding the UI `promptToken` (a raw UUID) as `session.prompt.id` receives HTTP 400 on OpenCode 2.1.4, while `msg_` + 32 lowercase hex is admitted. On the client's definitive `InvalidRequestError` only, the agent clears the brief and retries that exact prompt once without an ID, with a bounded redacted diagnostic; ambiguous timeout/network failures are not retried.
