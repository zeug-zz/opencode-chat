## Native source contract inspected

Read-only source copy: `tmp/scribe-v2-migration/policy/native-source/opencode`.

- `packages/schema/src/mcp.ts`: `ServerConfig` is a tagged union with `type: "local"` or `type: "remote"`. Local fields include `command: string[]`, optional `cwd`, `environment`, `disabled`, `codemode`, per-server timeout and protocol. Remote fields include `url`, headers, oauth (object or `false`), `disabled`, `codemode`, timeout and protocol. Both Code Mode fields are optional and documented default-on; explicit `false` must remain unchanged.
- `packages/schema/src/config/mcp.ts` and `packages/schema/src/config.ts`: current configuration is `mcp: { timeout?, servers?: Record<string, ServerConfig> }`.
- `packages/core/src/config/discovery.ts`: current file names are `opencode.json` and `opencode.jsonc`; sources include system, managed preferences on macOS, global, explicit, direct ancestor files, and `.opencode` project directories. Direct and project paths use ancestor discovery through filesystem root (not a nearest-git boundary). Source filtering avoids reloading global/system paths from the project walk.
- `packages/core/src/config.ts`: order is managed-policy entries, well-known, global supplementary, explicit, direct, project supplementary, process `OPENCODE_CONFIG_CONTENT`, then managed settings. Managed settings load last.
- `packages/core/src/config/plugin/mcp.ts`: server entries are applied in config order by name; later definitions replace earlier complete definitions. Global timeout fields merge in order and server timeout fields override them.
- `packages/core/src/config/plugin/policy.ts`: managed `integration.use` deny removes matching `mcp:<name>` servers after configuration composition.

## Implemented local contract

- `mcp-inventory.ts` now reads the supplied global config directory, native direct ancestor config files, and ancestor `.opencode` config directories in the observed ordinary-source order. It parses JSON/JSONC, validates supported native local/remote server fields, preserves complete validated definitions and global MCP timeout fields in memory, records source provenance, and reports explicit source-qualification gaps. Errors are bounded and exclude config payloads.
- `.mcp.json` is no longer treated as a V2 discovery source. It is not in the inspected current `ConfigDiscovery.names` contract.
- Direct legacy MCP entries are normalized as bounded pure input: `type: "local" | "remote"` identifies the form even without `enabled`; optional `enabled` must be boolean; records with no own `type` and boolean `enabled` are omitted before reserved-name handling, even when they contain extra keys. Native `mcp.servers` definitions coexist with direct entries and win duplicate names within a file. Per-server and global numeric timeouts expand to startup/catalog/execution and must be positive integers; native global timeout fields in the same file override `experimental.mcp_timeout` catalog/execution defaults. Legacy OAuth camelCase migration is limited to fields in the V1 schema; unknown or invalid credential fields are rejected through payload-free errors. Native `auth_server_metadata_url` remains accepted, but the V1 source schema does not define a legacy camelCase alias for it.
- `mcp-overlay.ts` emits native `mcp: { servers: ... }` definitions. It copies full selected definitions, uses native `disabled: false` for selected ordinary servers and `disabled: true` for unselected ones, preserves omitted `codemode` and explicit `codemode: false`, and does not fabricate a `locked: []` claim. Native managed sources load after process overlay and the managed policy plugin removes denied MCP entries; this ordering was source-inspected, not runtime-tested here.
- Extension startup and sandbox reconnect continue composing the same in-memory overlay through the existing shared launch-configuration path. No config write, direct secret lookup, schema dump, dispatcher, tool duplication, or persistent secret storage was added.
