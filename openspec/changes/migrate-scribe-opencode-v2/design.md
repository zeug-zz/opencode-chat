## Goals / Non-Goals

**Goals:** Establish an independently reviewed contract map before implementation; hold client imports within `packages/agents/opencode`; preserve core/host separation, actual enabled integration behavior, and all existing security boundaries; make unsupported required behavior a blocker.

**Non-Goals:** V1 coexistence, installation/link changes, shared-service management, SDK server embedding, user config/profile edits, external plugin changes, AF redesign/upgrade, nested nono, and deployment. The earlier dormant-Vibefeld non-goal is superseded only by the user-approved AF/Vibefeld first-class reasoning scope dated 2026-10-25 below. The user explicitly authorizes autonomous implementation and continuation for functional parity on V2; avoid repeated permission requests for local work. This is not authorization for externally consequential live host/provider/plugin operations, profile/config changes, or durable writes, which retain explicit authorization gates.

## Decisions

1. **One V2-only client adapter; one Scribe-owned foreground child.** The client package supplies HTTP access only; the stable executable starts `serve`. No `Service.ensure`, process-global cwd mutation as an architectural substitute, shared server, V1 fallback, or in-process server SDK. The exact client/server release and endpoint mapping are an initial blocking contract task, not guessed here. Alternative—rename old SDK calls—fails because the current package, server creation, wire formats, auth and event lifecycle are not proof of the V2 contract.
2. **Preserve supported user source formats; native V2 only for Scribe overlays.** Discovery/effective precedence must be proven across system/managed, global, ancestor/nested project, file definitions, and process overlay. No config writes or persistent config endpoint for overlay. Effective permission tests, not overlay inspection alone, determine acceptance.
3. **Separate local preparation from external qualification.** Bounded metadata/state tooling and hermetic API/mock-provider tests are local work and may be completed autonomously; they do not prove native discovery, installed plugin identity/source/version, or host parity. A distinct inherited-plugin lane verifies actual intended discovery inputs and expected identity/source/version while isolating mutable HOME/data/state/database/service registration. Neither lane is empty-inventory PASS. Existing package metadata is not plugin execution authorization. Task 1.4a records only the already verified 32 focused tests; 1.4b retains the actual-host/integration inputs and all missing source-inventory work.
4. **Preserve functions; report evidence honestly.** Codex plugin is delivered externally; qualify its loading/correlation/cancel/token-stripping/native retry and HTTP/process-alive limits without editing it. Hindsight retains plugin-managed daemon, injected runtime credentials, loopback endpoint and external PostgreSQL mapping. Vibefeld/AF remains host-private direct bounded execution under the enclosing boundary, no nested nono. Historical or fixture-only seams are not activated.
5. **Resolve behavior conflicts before implementation.** Existing TUI attach fallback is removed because the current companion is restricted. Ordinary user-config-disabled MCP must enable when Chat explicitly selects it; the V2 contract must be found or this mandatory behavior blocks migration. Higher-authority denials remain effective. Existing `setModel` file writes must be reconciled without config mutation. The user approved accepting V2's native keyed durable session-instruction channel, including the provider-level escaped `<system-update>` user-role serialization of chronological updates/removal. Initial instruction context remains system; Scribe must not substitute or append the brief into `session.prompt` user text. Preserve the exact native admission/history controls, FIFO, wait/Stop, and foreign-key behavior; this clarification is not a stronger authority or quality claim and does not itself pass runtime qualification. **Historical decision, superseded on 2026-10-25 for the reasoning-assist brief by the dated section below: the durable channel is not an implementation path or fallback for that brief.**
6. **Use native Code Mode without rebuilding V1 limits.** Scout, the reviewed worker, and Build-backed Write receive explicit native `execute`; restricted reviewers do not. Existing nested permission enforcement, authority denials, worker tool allowlist, and Write artifact-edit scope remain controlling. Native MCP Code Mode stays enabled by default for selected complete server definitions; explicit `codemode: false` remains a direct-tool choice. Accept native `fetch` including methods, headers, and bodies: it is not the permission-checked `webfetch` tool, and Scribe adds no interpreter, network, time, output, call, or concurrency caps. Existing OS/network backend controls still apply; sandbox-off is not OS containment. The pinned interpreter inspection describes native behavior, not a Scribe guarantee.

## Risks / Trade-offs

- [Unverified client/server/auth contract] → block launch implementation until the exact client/package identity, endpoint, auth and version contract pass a disposable contract spike; production version eligibility remains the stable `>=2.1.3,<3.0.0` policy above, with all runtime/schema checks independently enforced.
- [Native config/MCP precedence differs from current assumptions] → source-format fixtures plus effective server behavior tests; no guessed overlay.
- [Provider-level serialization of native instruction updates is lower-authority user-role content] → the 2026-10-21 acceptance of the native keyed channel and its escaped `<system-update>` serialization is historical and is superseded for the reasoning-assist brief by the 2026-10-25 ephemeral-plugin decision below; do not use the durable channel as a fallback. The new plugin boundary and outgoing-call-only behavior require their own spike and qualification.
- [Actual host/injection evidence needs external inputs] → the user stopped the formal isolated-host/live/soak programme on 2026-10-30. Required external gates remain deferred and unverified, not passed or waived; release acceptance stays blocked. AF continues under its existing direct-execution readiness and enclosing sandbox; no separate AF policy/grant preflight is introduced.
- [Session share/unshare unavailable on the V2 pair (server 2.1.2, `@opencode/client` 2.1.0)] → user-approved feature reduction on 2026-10-22, not a V2 parity claim. Neither the server nor the client exposes a share/unshare endpoint or method (only the config field `share`). The adapter throws `OpenCodeOperationUnavailableError` and reports `sessionShare: false` behind the existing `requireCapability("sessionShare")` host gate, as the spec's "Report unsupported outcomes honestly" requirement permits for optional operations; the approved intent is that the UI hides or disables share. Re-evaluate if upstream adds a share API.
- [Enabled AI-SDK-provider transport cancellation is upstream] → approved scope decision 2026-10-22, made under the user's standing approval of recommendations. Native 2.1.2 `core/src/aisdk.ts` still calls `language.doStream(options)` without forwarding an abort signal (lines ~729-731). Its fetch wrapper (lines ~135-170) merges only init/header/chunk/timeout signals. Scribe's Stop uses the native `session.interrupt`, the same path the independent TUI uses. Native then interrupts the step and cancels stream consumption, but whether an AI-SDK provider aborts its underlying HTTP request depends on that provider. This limitation is shared with the TUI and is not patched by Scribe (no native/plugin edits). Scribe-side Stop outcomes are qualified by the bounded native Stop fixtures (adapter 2.6 `a658923d` 68/68 and question-cancel `0923804a` 28/28). The three historical custom-provider FAIL manifests are retained. Re-evaluate if upstream forwards the signal.
- [Plugin-free fallback replaced by native per-plugin failure isolation (2026-10-23, user-approved recommendation)] → Native 2.1.2 catches plugin import/export/activation failures and lists the plugin as failed while the server stays ready (source: core/src/plugin/supervisor.ts:33-120, plugin.ts load/slotInfo; runtime PASS tmp/scribe-v2-migration/plugin-failure/9f2d9e1d-e5dd-4049-9bbc-ccc40676a1df/result.json 22/22). A config-level plugin-free relaunch is not expressible (plugin operations accumulate across documents; removals apply after module loading, source.ts:113-160). The dead always-false `pluginFree` path, whose `plugins: []` overlay removed nothing, was deleted. Readiness/auth/version failures remain non-retryable; no backend downgrade.

### Decisions and rationale

1. **The brief is ephemeral and outgoing-call scoped.** The architect's validated, concise argument map is delivered only to the current Scout session/turn. A Scribe-owned V2 plugin applies a matching brief from the outgoing `session.hook("context")` hook. V2 plugin behavior is relied on only after the spike verifies that this hook runs before model calls and that its changes affect the outgoing call without changing history or configuration. The brief may include bounded, calibrated AF recorded-structure status, but no critic objection, raw AF output, AF ledger, proof path, or unsupported truth/proof claim. AF execution and claim projection remain host-owned, with no model-visible AF executable, path, argv, or invocation route.
2. **Use a narrow, bundled plugin boundary.** The plugin ships inside the extension, is hash-verified before loading, has no tools and registers no model/tool route, and is added only to Scribe's private server through the process-scoped in-memory overlay. It is never added to user/project `opencode.json`, global configuration, or an independent TUI. Its failure or hash mismatch disables reasoning assist only; ordinary Chat remains available.
3. **Do not make ordinary turns wait for semantic classification.** A deterministic model-free pre-screen skips only obvious greetings, thanks, acknowledgements, and empty/near-empty turns. It MUST NOT skip on length alone. For other eligible Scout prompts, the existing architect remains the sole semantic classifier and runs in parallel with prompt admission. A semantic `ordinary` result leaves the prompt unchanged and creates no UI. This avoids a second model classifier and keeps ordinary dispatch off the assist critical path.
4. **Bound only the first argument-call grace.** Classification runs in parallel with prompt admission, and ordinary prompts never wait for it. Only after a valid map confirms an argument turn may its first outgoing model call wait for the brief within a configured grace window whose hard ceiling is 2 seconds. The exact value is selected from measured latency and recorded as evidence. If no brief is ready by the deadline, that call proceeds without it; once a later result becomes available, the plugin attaches it to every subsequent outgoing model call for the same still-active turn. The grace wait is never repeated. If the turn finishes before classification and no further current-turn call remains, discard any late result without marking assist as applied or synthesizing a continuation, extra response, or rewrite. Prompt admission itself is not held. A new prompt, Stop, turn completion, session change, or reconnect clears pending state and prevents late or cross-session delivery.
5. **Keep model work selective and policy-exact.** Hidden native `chat-reasoning-critic` (devil's advocate) and `chat-reasoning-verifier` subagents are available only to Scout when warranted; a brief may recommend a call but does not compel one. Each role is limited to one call per turn, may run asynchronously in the background, and returns schema-bounded output. These agents have no file, MCP, `execute`, web, AF, Hindsight, or delegation authority; restricted agents receive explicit `execute` denial. The task target policy is exact: Scout may delegate only to `chat-research-worker`, `chat-reasoning-critic`, or `chat-reasoning-verifier`, with wildcard denial for every other target. Write is excluded.
6. **Make completed-answer review explicit and separate.** A localized `Review argument` action is available only as a secondary action on completed assistant messages, not as a large/prominent primary button on every answer. The host routes a typed request/result through `packages/core/src/protocol.ts` and `chat-view-provider.ts`; a generation-bound hidden architect maps the completed answer as untrusted data through the existing packet builder/parser before AF receives only the validated graph. AF claim projection remains authoritative; prover/verifier objections become bounded `openChallenges` and never upgrade AF status. Reuse existing cancellation, stale-result checks, hidden-session registry, and 60-second total / 30-second stage budgets. There is no answer hold, response rewrite, automatic re-audit, or model-visible AF route. Dedicated review-result and thinking Markdown copy actions are not part of the current UI; main-answer copy remains unchanged. The historical V1 plan described post-response review, but its arbitrary answer prose did not match AF's private line protocol. Code review established only that `0.17.1` lacked a post-response route; this does not establish whether any V1 runtime shipped it. A user-requested typed review is distinct from automatic post-response auditing. On-demand subagents are chosen over unconditional critic calls so non-argument turns incur no reviewer call and Scout can request only the bounded role relevant to the turn.
7. **Rebind readiness and keep diagnostics local.** A reconnect-safe restricted-review holder rebinds and reruns readiness after every successful connect, including sandbox toggles and event recovery; stop/failure invalidates it, cancels in-flight work, and republishes `reasoningRuntime`. AF discovery/preflight remains once per activation. If no saved preference exists, assist SHALL default on when AF is detected and ready; an explicit user value, including `false`, and the workspace opt-out SHALL be preserved. Architect, critic, verifier, and review stages use OpenCode's native resolved effective DEFAULT model through its location-bound API, pinned and validated against the current connection generation. This honors a configured OpenCode default without requiring a literal top-level `model` field; no Scribe-specific model setting, config write, arbitrary catalog fallback, or Scribe UI-selected model is permitted. Null, malformed, or failed resolution yields visible unavailability with a fixed reason. Diagnostics and latency timings go to Output → OpenCode Scribe, are bounded and redacted, and never contain prompt text, model output, paths, IDs, credentials, or configuration contents.
8. **Give each automatic assessment its own review lifecycle.** The host creates a fresh restricted provider pinned to the current connection for each detached automatic assessment, checks its readiness, and begins a fresh review token before creating any hidden session. That assessment owns the token and child cleanup through success, ordinary completion, failure, timeout, cancellation, supersession, and reconnect. It never shares or cancels the manual-review provider's lifecycle; the provider's `createSession` token guard remains unchanged. A token returned after cancellation is cancelled and cannot authorize a session. Manual completed-answer mapping uses the already-begun manual review lifecycle through a separate adapter entry point, so it cannot accidentally enter automatic ownership.

### Data flow and trust boundary

The current UI provides no dedicated `Copy review as Markdown` or per-segment `Copy thinking as Markdown` action. Manual `Review argument` remains a secondary action on completed assistant messages; it is not a prominent primary button on every answer. The existing main-answer copy action and its behavior remain unchanged. Historical local acceptance of the former review/thinking copy controls is recorded in tasks 6.7a and 4.4a; task 6.7b supersedes only those copy-control requirements and preserves the underlying review and reasoning-segment behavior.

The host performs the model-free pre-screen. If not skipped, it starts the existing restricted architect as the only semantic classifier while admitting the unchanged Scout prompt. Only a validated argument map can produce a size-bounded concise brief, which may also include bounded calibrated AF recorded-structure status but no critic objections, raw AF output, ledgers, proof paths, or unsupported truth/proof claims. The host delivers it over a session/turn-keyed channel chosen and documented by Task 6.3. The bundled plugin verifies the hook's session and agent identity, matches the current turn, and modifies only that call's outgoing model context. It retains no brief in history, durable instructions, or configuration. The plugin's own permissions are tool-less; the V2 private child, not the independent TUI, is the only load target. An unknown session/agent, stale key, oversized payload, plugin error, hash mismatch, or unavailable channel is a no-assist result, never a reason to broaden authority or block normal Chat.

The private plugin context hook filters model tool definitions only for the exact identities `vibefeld-restricted-review`, `chat-reasoning-critic`, and `chat-reasoning-verifier`; the `session.generate` hook filters only `vibefeld-restricted-review`. The restricted filter requires a plain tool map, removes every own key, and verifies that no key remains. A missing or malformed container, a thrown filter operation, an unremovable definition, or a nonempty result raises a fixed error from the restricted branch and aborts that request before provider dispatch. This definition filtering grants no authority; native permission and execution-denial hooks remain in force. The restricted error path is separate from the Scout brief-injection path and is not caught by it. Scout brief injection remains total and fail-open: an internal error or expired grace skips the brief and lets ordinary Scout generation continue. Pinned OpenCode 2.2.0 native fixtures verify zero definitions on restricted generate and prompt requests, no provider request after an injected restricted generate-hook failure, and successful subsequent Scout generation; these are isolated fixture results, not host guarantees. Plugin absence/failure disables reasoning assist while preserving ordinary Chat; 2.1.3 evidence is source-availability only.

Architect results remain exact-schema JSON. The parser may remove one complete
outer Markdown fence (optionally labeled `json`, case-insensitively) only when
the body is bounded by newlines and no non-whitespace surrounds the fence; the
existing length limit applies to the original text, and all schema, key, type,
safety, and graph checks remain unchanged. Prose-wrapped JSON and multiple
fences are rejected. The fixed architect instruction also states the claim
graph rules that validation enforces. A `missing-dependency` parse failure adds
one first-match fixed sub-reason derived from the parsed graph, never graph
content, to bounded diagnostics. Diagnostics record fence normalization
through a fixed enum, not result content.

For completed-answer review, the explicit host request maps only the selected completed answer through the existing generation-bound architect packet builder/parser, framing it as untrusted data rather than current user text. Malformed, unsafe, ordinary, or over-limit mappings stop before AF; no answer is truncated. Only the validated graph enters the existing bounded AF claim packet and review lifecycle. The AF claim projection remains authoritative; restricted prover/verifier results are normalized independently as open challenges. Scout's on-demand critic/verifier calls are separate exact native subagent targets and do not route AF or expose hidden review data to Write, the worker, MCP, or tools.

Reviewers receive the normalized compressed graph and evidence-status metadata, not the full answer or source contents. Mapping preserves explicit answer premises and self-contained support; citations and source findings are intentionally omitted, so their absence is not proof that the original answer omitted them. Fixed public Review limits disclose compression. This provides no content guarantee or proof of fidelity and adds no sources, tools, model calls, packet/schema expansion, raw review data, or AF route; AF authority is unchanged. An incomplete compressed packet is distinct from an original-report defect: a verifier does not confirm objections solely from omitted raw citation content, and actual insufficiency may remain unresolved, while substantive graph and empirical-support weaknesses remain assessable.

### Spike exit criteria and failure handling

Task 6.3 MUST pass before implementation of the Scribe plugin or ephemeral brief. It records: (a) reliable session and agent identification in `session.hook("context")`; (b) an outgoing-call-only mutation with no persisted history or durable configuration change; (c) a host-to-plugin delivery mechanism, such as plugin RPC, selected from verified options; (d) session/turn key isolation, size bounds, and clearing; (e) per-plugin failure isolation that leaves Chat usable; and (f) a measured comparison of `session.generate` against hidden sessions for classifier latency and no-tools behavior. The report includes the selected mechanism, exact bounded checks, limitations, and latency observations without prompt/model contents. If any required criterion fails or cannot be established, stop the reasoning-assist implementation and ask the user to choose a revised design; do not fall back to `scribe.prompt-context` or another durable channel.

**Spike outcome (2026-10-25, OpenCode 2.1.4):** PASS (a)–(f) under a sandbox-off isolated fixture with a local mock provider. The selected delivery is authenticated host-to-plugin RPC; the context hook must be total. Task 6.5 adds its sole permitted await: one plugin-capped (maximum 2-second) in-memory grace promise for a matching host-confirmed pending argument turn; it performs no I/O and fails open on errors or expiry. The native uncaught-throw residual limitation is that a context-hook throw can silently complete a turn without a model call and does not disable the plugin. Classification uses `session.generate` on the hidden restricted agent. Sandbox-on, packaged/hash-verified delivery, and actual-host behavior remain for Tasks 6.4/6.9.

### Source findings and risks

The following are current-code review findings, not proven causes of the 2026-10-24 host-smoke result: the current brief is appended by `chat-view-provider.ts` and persisted by `opencode-agent.ts` through `setPromptContext` as `scribe.prompt-context` (serialized by V2 as `<system-update>` history entries); architect preflight currently blocks admission of every eligible Scout prompt; the restricted-review provider is created once at activation and bound to `connectionGeneration`, so later generation changes can leave it stale until reload; reasoning outcome logs use `console.*` rather than the `OpenCode Scribe` output channel; the adversarial controller's `review()` has no request in the current protocol; and the 2026-10-24 RC7 smoke observed chat but no AF activity. The first two observations motivate the ephemeral channel and off-critical-path assessor; the others motivate holder rebinding, diagnostics routing, manual typed protocol, and actual-host acceptance. None establishes the cause of host silence.

Risks are bounded as follows: the plugin hook/channel may not expose stable session identity or may persist changes, so the spike is a hard gate; hashing and private-overlay construction must be tested against packaged bytes and must never affect the user's TUI; the grace value may be insufficient for the architect/AF work, so a late brief is limited to remaining model calls in the still-active turn and never delays ordinary prompts; the default applies only when no saved preference exists and depends on AF detection and readiness, preserving explicit opt-out; the host's top-level model can be absent or malformed, in which case the feature is visibly unavailable rather than selecting another model; and actual-host claims remain pending until Task 6.9 evidence exists.
